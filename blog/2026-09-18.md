# How I started this blog

I stopped doing things I used to enjoy. I used to express myself through code, as for me, writing code felt like it was a creative moment, I could tweak the problem that I'm working on and the constraints so that I made sure that I was always learning something, and there was always room for a little creativity.

With the recent advancement in agentic engineering, coding by hand feels like digging a huge ditch with a spoon, while there is a huge excavator available. Sure it could be more precise, smoother, and fulfilling, but still, a hole is a hole and the excavator does it in the blink of an eye. But my itch to be creative, and to think deeply not only about the problem, but also about every intricate detail of the problem, is still there unfulfilled.

So, this blog will scratch that itch, I will turn to writing, not code this time, but blog posts, not to perform for someone, but just for me, doing it because I enjoy those exact moments.

Sure, I could write by hand the same way I'm writing this blog post, but in reality, I'm not being paid for these blog posts and nobody expects me to finish this blog post in an hour, I'll finish this post when I consider it to be finished.

Good, now that I came up with the idea of writing. How do I start a blog?

Initially I considered fully vibe coding it and uploading it to Cloudflare, but it felt a bit like cheating, writing blog posts by hand but the tech behind it AI generated?

While searching for tools and alternatives to that, I stumbled upon an old promise that I made here <http://github.com/stefanm8/stefanm8.github.io/commit/49067a6839aa2892b776fa8d7a43220bf259b4c1>

Now is the time to deliver on that promise: build out the machinery behind the blog, write as much as possible by hand.

The constraints were simple and direct: I must be able to finish this feat fast, a few hours maximum, it must cost me $0, and it should have as few dependencies as possible.

Stripping down to primitives, what do I actually need in order to have a blog?
- text editing
- storage
- webserver

So for text editing, I'll rely on vim, storage will be git, and the webserver will be GitHub Pages.

The components that I had to manually write:
- one line of CI
- a few lines of Python to render markdown to HTML
- a few lines of JavaScript
- copy one file from https://github.com/trentm/python-markdown2

The last one feels a bit like cheating, but yeah, writing my own markdown renderer seemed like a feat I couldn't accomplish in less than an hour, which is the time I gave myself for finishing this.

One hour in and I delivered what I set myself to deliver: a fully functional blog.

Sure, I had a concern that agents have caused havoc on my abilities to write and think. Writing this by hand made it a certainty, not only did it feel hard, it felt painful. It felt like I'd lain in bed for more than a year, and right now I'm starting to walk again. Sure, I did it, but I'm wondering, why did I stay in bed so long?
